# Самостоятельный поисковый сервис

Редактируемый шаблон backend-поиска: HTTP API на Python/FastAPI, BM25 на Rust/Tantivy. Проект собирается отдельно от MAS Crawler, не импортирует Gather и не требует агентов, LLM-ключей или доступа к исходному конструктору. Пользовательский интерфейс заказчика обращается к этому API из своего backend.

При ручном копировании шаблона включён небольшой явно искусственный корпус с адресами `example.invalid`; это демонстрационные документы, не результат обхода и не оценочный benchmark. В Gather можно экспортировать выбранный BM25-эксперимент со страницы «Оценка»: экспортёр подставляет полный корпус источника, настройки и отдельную инструкцию запуска.

## Быстрый запуск

Нужны Python 3.12+, uv, Rust с edition 2024, C-компилятор и линкер. Сборка первоначально загружает зависимости из реестров; полностью офлайн-сборка не предусмотрена.

Скопируйте весь этот каталог в отдельное место, перейдите в него и выполните:

```sh
uv sync --locked
uv run --locked search-service build
uv run --locked search-service serve
```

Сервис по умолчанию слушает `127.0.0.1:8000`. API-документация доступна на `/docs`, схема — на `/openapi.json`.

```sh
curl http://127.0.0.1:8000/health
curl -X POST http://127.0.0.1:8000/search \
  -H 'Content-Type: application/json' \
  -d '{"query":"shared state", "top_k":5}'
```

`POST /search` принимает `query` и необязательный `top_k` (1–100, по умолчанию 10). Ответ содержит нормализованный запрос и `hits`: `id`, `url`, `title`, `score`. Сейчас ID равен уникальному URL исходного документа; score — оценка BM25, не вероятность. Поиск трактует запрос как обычный текст, а не язык запросов. Фильтров, фрагментов текста, подсветки, векторного поиска и reranker пока нет.

Индекс открывается один раз при запуске. Для каждого запроса создаётся лёгкая конфигурация поиска над тем же индексом. При отсутствии или повреждении индекса запуск завершается ошибкой, а не запускает скрытую пересборку.

## Данные и конфигурация

`data/documents.jsonl` содержит по одному JSON-объекту на строку с непустыми `url`, `title`, `text`. URL должны быть уникальны. Замените пример своим корпусом из MAS Crawler: формат тех же трёх полей уже поддерживается. Неверный JSON, пустые поля, повторяющиеся URL и пустой корпус отвергаются.

`search.toml` задаёт пути и веса. Относительные пути считаются от каталога TOML, даже если команда запущена из другого рабочего каталога. Неизвестные настройки, неподдерживаемая версия формата и недопустимые веса вызывают ошибку.

Изменение `title_weight` и `text_weight` требует перезапуска сервиса, но не пересборки индекса. Прямые настройки HTTP API находятся в `src/search_service/app.py`; состав поисковой цепочки — в `src/search_service/search.py`; реализация BM25 и схема индекса — в `native/src/search.rs`. Эти исходники можно редактировать. После изменения Python/Rust-кода выполните `uv sync --locked --reinstall-package search-service`; после изменения схемы или обработки индексируемого текста также постройте новый индекс.

Изменение корпуса само по себе не обновляет выдачу. Постройте новую версию:

```sh
uv run --locked search-service build --output indexes/v2
```

Затем укажите `index = "indexes/v2"` в `[storage]` и перезапустите сервис. Путь `--output`, в отличие от путей TOML, считается от текущего рабочего каталога. Предыдущий индекс не изменяется; для отката верните старый путь. Команда никогда не перезаписывает существующий каталог индекса. Это ручное переключение с перезапуском, не атомарный hot reload и не обновление без простоя.

Внутри каждого нового индекса сохраняется `build.json`: версия движка, число документов и SHA-256 корпуса. Это сведения о сборке, не подтверждение качества. Не меняйте корпус во время сборки. При прерывании записи может остаться неполный индекс; используйте новый каталог или вручную удалите заведомо нерабочий.

## Собственная интеграция

Backend заказчика вызывает `POST /search` и отображает ответ в собственном интерфейсе. Никакого обращения к Gather нет. Python-код обработки и Rust-код поиска входят в поставку; проект не ссылается на соседние каталоги MAS Crawler.

Для разработки запускайте тесты и проверки:

```sh
uv run --locked pytest
uv run --locked ruff check src tests
uv run --locked ruff format --check src tests
cargo test --locked --manifest-path native/Cargo.toml
cargo fmt --manifest-path native/Cargo.toml -- --check
```

`uv.lock` и `native/Cargo.lock` фиксируют зависимости. При осознанном обновлении зависимостей обновите соответствующий lock-файл и повторите тесты.

## Docker

Из корня скопированного проекта:

```sh
docker build -t my-search .
docker run --rm -p 127.0.0.1:8000:8000 my-search
```

Образ собирает индекс из включённого корпуса. Для собственных данных замените корпус перед сборкой. В образе используется установленный пакет, а не editable-ссылка на исходный checkout. Контейнер запускается без root; его процесс слушает `0.0.0.0`, но пример публикует порт только на loopback хоста.

Сервис не содержит аутентификации, TLS, ограничения частоты запросов или управления доступом к документам. Для публичного/корпоративного развёртывания добавьте необходимые ограничения в инфраструктуре заказчика и при необходимости в приложении. Не публикуйте этот пример напрямую в интернет. Не включайте секреты в исходники или Docker build context.

## Граница конструктора и шаблона

`native/src/search.rs` — точная копия поисковой реализации конструктора на момент подготовки шаблона. В репозитории конструктора `tools/sync_search_template.py --check` проверяет отсутствие расхождений, а запуск без `--check` обновляет снимок. Для независимого проекта этот инструмент не нужен: заказчик может менять свою копию без синхронизации с Gather.

Экспорт Gather включает `export.json` с настройками и происхождением выбранного эксперимента. Разметка и полные отчёты качества не прикладываются. Проверки шаблона подтверждают выполнение поиска и изменение конфигурации на искусственных примерах, а не качество на реальных пользовательских запросах. После пересборки индекса порядок документов с одинаковым BM25 score может отличаться; сам экспорт не является повторной оценкой качества.

Для будущего dense/hybrid-поиска точкой расширения служит `search.py`. Реализацию и дополнительные зависимости нужно добавить явно; изменение TOML само по себе не создаёт новый механизм поиска.
